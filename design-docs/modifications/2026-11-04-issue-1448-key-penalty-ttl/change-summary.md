# Issue #1448 变更摘要：Key 惩罚时长可配置（控制面）

## 1. 背景

BFE 对上游失败的 Provider API-Key 会写一个 Redis 惩罚键（`{prefix}:penalty:{cluster}:{key_name}`），惩罚窗口内选 Key 跳过它。两档时长此前是数据面代码常量：429 为 60 秒、401/402/403 为 3600 秒，控制面没有对应字段，运营既看不到也改不了。

2026-10-22 的 kimi 集群事故（2 把 Key、其中 1 把 `Weight=0`，连续 6 次上游 401）中，每次 401 都写入 3600 秒惩罚，惩罚状态存在 Redis、重启 BFE 也无法清除，只能等过期或人工删键，降级约 2 小时。

数据面已把两档时长改为集群级配置（`AIConf.KeyPolicy.SessionAffinityPenaltyTTL429` / `...Auth`，默认 60 / 300 秒，见 bfe 仓库 `docs/zh_cn/modifications/2026-11-04-issue-1448-configurable-key-penalty-ttl/`，fork 提交 `904ceab1`）。本变更负责控制面：OpenAPI 字段、入库默认值、导出映射、范围校验与契约文档。

## 2. 目标

1. OpenAPI `llm_config.key_affinity` 新增 `penalty_ttl_429` / `penalty_ttl_auth`（整数秒），默认 60 / 300。
2. 「不填 = 默认值」在控制面成立：入库前补默认，导出时再兜一层，与数据面默认值同源。
3. 显式非法值被拒：`penalty_ttl_429` ∈ [10, 600]、`penalty_ttl_auth` ∈ [60, 1800]；`0` 与负数一律 422，**`0` 不表示关闭**。
4. 契约文档与集成 schema 断言同步。

## 3. 影响面

| 层 | 变化 |
|----|------|
| OpenAPI | `llm_config.key_affinity` 增 2 字段；PATCH 复用同一请求体，无需新增接口 |
| InnerAPI 导出 | `AIConf.KeyPolicy` 增 `SessionAffinityPenaltyTTL429` / `...Auth`，值恒为具体秒数 |
| DB | 无 DDL：两个字段落在 `clusters.llm_config` 的 JSON 文本里 |
| 数据面 | 旧 BFE 忽略未知字段；本次控制面改动不改变旧 BFE 的 60/3600 行为 |
| Web | 表单与默认值由前端单独跟进（本变更只保证接口与契约） |

## 4. 关键决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 凭证档默认值 | **300 秒**（原 3600） | 5 分钟足够止血，同时把误判自愈时间从 1 小时压到 5 分钟；小于绑定空闲超时 600 秒，恢复后绑定仍在 |
| `0` 的语义 | 拒绝（422），不作为「关闭」 | Redis `SETEX key 0` 是「永不过期」；且与「缺省 = 默认值」冲突，会让运营以为能关掉惩罚 |
| 字段命名 | `penalty_ttl_429` / `penalty_ttl_auth` | 与同层 `penalty_enable` 对齐；不复用 `ttl`（那是绑定空闲超时，默认 600） |
| 控制面范围 vs 数据面上限 | 控制面更严（600 / 1800），数据面仅 86400 防呆 | 控制面是第一道闸；数据面截断而非报错，避免手工改配置导致 reload 失败 |
| 是否做跨字段校验 | 不做（不要求 auth ≥ 429） | 两档语义独立，`429=600 / auth=60` 是合法组合 |

## 5. 兼容与发布

| 组合 | 行为 |
|------|------|
| 新控制面 + 新 BFE（未配置） | 导出 60/300，与 BFE 默认一致 |
| 新控制面 + 新 BFE（已配置） | 按配置生效，改配置后下一次惩罚写入即生效（无需重启） |
| 新控制面 + 旧 BFE | 旧 BFE 忽略未知 JSON 字段 → 退回 60/3600，**用户配置静默失效** |
| 旧控制面 + 新 BFE | 导出缺字段（解码为 0）→ BFE 加载期补 60/300 |

发布顺序：**bfe → ai-gateway-api → ai-gateway-web**。反序会让配置在旧数据面上静默失效。回滚控制面后已保存的字段只是被旧版本忽略，无破坏。
