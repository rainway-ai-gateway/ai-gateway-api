# 接口层设计文档

## 1. 概述

本文档描述 `ai-gateway-api` 接口层（`endpoints` 包）的当前实现结构，包括管理面 OpenAPI（`/open-api/v1`）和数据面 Inner-API（`/inner-api/v1`）的路由组织、中间件链、子包划分以及典型接口的实现模式。

接口层采用统一的 `xreq.Endpoint` 抽象：

```go
type Endpoint struct {
    Path string
    Method string
    Handler Handler
    Authorizer func(*http.Request) error
    RegisterHandler func(*mux.Router) *mux.Route
}
```

每个子包导出自己的 Endpoint 变量切片，最终在 `endpoints/openapi_v1/endpoints.go` 或 `endpoints/innerapi_v1/endpoints.go` 中统一合并注册到 `gorilla/mux` 路由器。

## 3. 中间件设计

全局中间件在 `endpoints/router.go` 的 `RegisterRouters` 中注册，执行顺序为：

```go
router.Use(middleware.MCRecovery)
router.Use(middleware.MCLogger)
router.Use(middleware.McIPProbe) // 管理面 IP 白名单；位置约束：Logger 后（拒绝留痕）/ CORS 前（403 对预检生效）；勿移
router.Use(middleware.MCCors)
```

各路由子树再按需挂载业务中间件：

- `/open-api/v1`：`McProductProbe` + `McUserProbe`
- `/inner-api/v1`：仅 `McUserProbe`

| 中间件 | 文件 | 作用 |
|--------|------|------|
| MCRecovery | recovery.go | 捕获 panic，返回统一错误响应 |
| MCLogger | access_logger.go | 记录请求/响应日志 |
| McIPProbe | ip_probe.go | 管理面 IP 白名单：按路径分组规则校验客户端网段（支持可信代理 XFF 解析与 Audit 观察模式），未命中返回 403；默认关闭，配置见 `stateful/config.go` 的 `[AccessControl]`，支持 monitor 端口 `/reload/access_control` 热加载 |
| MCCors | cors.go | 处理 CORS 预检和响应头 |
| McProductProbe | product_probe.go | 从请求头解析产品线上下文 |
| McUserProbe | user_probe.go | 从 Session Key 或 Token 解析用户身份，完成权限校验 |
| Convert | convert.go | 负责 `xreq` 与标准 `http.Handler` 的适配 |

`McUserProbe` 会调用每个 Endpoint 上配置的 `Authorizer`（由 `iauth.FA` 或 `iauth.FAP` 生成），根据 Feature + Action 判断是否放行。

## 4. OpenAPI v1 接口层

路由前缀：`/open-api/v1`

### 4.1 路由注册

```go
// endpoints/openapi_v1/endpoints.go
func RegisterEndpoints(router *mux.Router) *mux.Router {
    openAPIV1Router := router.PathPrefix("/open-api/v1").Subrouter()
    openAPIV1Router.Use(middleware.McProductProbe, middleware.McUserProbe)
    for _, one := range endpoints() {
        one.Register(openAPIV1Router)
    }
    return openAPIV1Router
}

func endpoints() []*xreq.Endpoint {
    return merge(
        product.Routers, // 保留（产品线管理）
        product_cluster.Endpoints, // 精简：移除 model-providers、models
        certificate.Endpoints, // 新增证书详情
        product_pool.Endpoints, // 保留
        subcluster.Endpoints, // 保留但对外空切片（当前未注册）
        auth.Endpoints, // 精简：移除 product 相关端点
        traffic.Endpoints, // 保留
        bfe_cluster.Endpoints, // 保留但对外空切片
        route.Endpoints, // 保留（表达式校验）
        domain.Endpoints, // 保留但对外空切片
        api_key.Endpoints, // 移除 generate 端点
        entity_type.Endpoints, // 保留
        entity.Endpoints, // 保留
        global_route_rules.Endpoints, // 保留
        route_tables.Endpoints, // 保留
        model_price.Endpoints, // 新增：模型定价管理
        operation_log.Endpoints, // 新增：操作日志查询
        provider.Endpoints, // 新增：Provider 管理
        epp_pool.Endpoints, // 新增：EPP 实例池（/epp-pool）
        epp_assignments.Endpoints, // 新增：EPP 分配查询与手工覆写（/epp-assignments）
        ai_cache.Endpoints, // 新增：AI 缓存规则（/ai-cache-rules，集合全量读写）

}
```

### 4.1.5 通用响应与错误码

- 返回值中**不再包含 `WorkMode` 字段**，统一返回 `{ErrNum, Data, ErrMsg}`。
- **新增错误码 `401` 表示鉴权失败**；`402` 表示没有调用权限；`510` 未启用。

#### 4.2.6 Provider（provider）、集群（product_cluster）、模型定价与模型访问协议

代码位置：`endpoints/openapi_v1/provider/`、`endpoints/openapi_v1/product_cluster/`、`endpoints/openapi_v1/model_price/`

> 说明：Provider 与 Cluster 概念分离后，`/providers` 集中管理接入能力（`model_endpoint`、`models`、`keys`、`instance_pool`、`model_protocols`），并通过 `time_zone` / `tiers` 描述高峰/闲时时段规则；`/clusters` 只保留转发策略。`llm_config.provider` 必填，且必须引用 `/providers` 中已存在的 Provider；`llm_config.models` 须为 Provider `models` 的子集；`llm_config.keys` 元素结构变为 `{name, weight}`，通过 `name` 引用 Provider 中的 key，不再返回 key 明文。`llm_config.model_endpoint`、`llm_config.provider_type` 已删除。`llm_config.model_mappings` 字段仍使用 `source_model`/`target_model` 描述模型映射；`llm_config.key_policy` 用于声明选择策略、请求内重试与退避参数；`llm_config.key_affinity` 用于声明基于 Redis + `ClientKeyId` 的会话级 Key 亲和性（含开关、空闲超时、Redis 前缀、Key 惩罚）；`llm_config.normalize_upstream_error` 用于声明上游错误体归一（统一错误码：非流式/流式独立开关、未识别处理、错误体上限、凭证脱敏，按集群灰度，缺省关闭）。InnerAPI 据此自动填充 `AIConf.ModelTable`：从 Provider 取 `time_zone` / `tiers`，从 `model-prices` 取 `prices` / `tier_prices`，并将 Provider 的 `model_protocols` 透传为 `AIConf.ModelProtocols`；`llm_config.model_table` 不在 OpenAPI `/clusters` 中展示。集群实例 `weight=0` 表示不接收流量，不会被后端强制改为默认值。`/clusters` 另新增 `balance_mode`（默认 `WRR`，可选 `EPP`）与 `epp_config`（简化用户形态的 EPP 调度配置，EPP 模式必填、WRR 时休眠保留）两个字段，EPP 模式 cluster 的 EPPAddr 由分配驱动生成（详见 `epp_pool` / `epp_assignments` 域）。
>
> **更新与删除约束**：
> - `PATCH /providers/{provider_name}` 的请求体**不能包含 `name`**；名称由 URI 路径参数唯一指定，若请求体携带 `name` 返回 422。
> - `PATCH /clusters/{cluster_name}` 的请求体**不能包含 `name`**；名称由 URI 路径参数唯一指定，若请求体携带 `name` 返回 422。
> - `DELETE /clusters/{cluster_name}` 在级联清理前，会检查该集群是否被 **AI 路由规则**（global / entity / api-key 级别）引用；若被引用，删除失败并返回引用冲突错误。

#### 4.2.13 批量任务（batches）

代码位置：`endpoints/openapi_v1/batches/`

> 说明：批量任务管控域（2026-10-07 新增，配合 BFE `mod_ai_batch`，详见 [details/批量任务与对账.md](./details/批量任务与对账.md)）。任务实体由对账 job 从 Redis `BATCH_TASK` 同步落库（`batch_tasks` 表），详情查询 DB miss 时回源 Redis（覆盖 job 落库前窗口），再 miss 返回 404 `BATCH_NOT_FOUND`；`product_name` 由 `McProductProbe` 强制注入，不接受外部传参。金额字段（`reserve_units` / `settle_units`）为 1e-8 定点整数、单位 RMB。cancel 由控制面直调 provider（前置依赖：控制面 → provider 出网；不允许出网的部署降级为仅展示），写操作进 `operation_logs` 审计。

| POST | `/batches/{batch_id}/cancel` | 取消批量任务（控制面直调 provider）：DB 条件更新抢占（affected_rows=0 → 409）→ 出网 POST provider cancel → 置 `cancelling` + Redis 幂等释放预留 → `operation_logs` 审计 | `FeatureBatch + ActionCancel` |

> 错误码：任务不存在（DB 与 Redis 均 miss）404 `BATCH_NOT_FOUND`；cancel 时任务已终态/他实例处理中 409 `BATCH_TERMINAL_OR_CONFLICT`；provider 不可达 502 `UPSTREAM_UNREACHABLE`；provider 返回批量不存在 404 `BATCH_NOT_FOUND`（透传 provider 语义）。cancel 端点内部流程与竞态收敛见 [details/批量任务与对账.md](./details/批量任务与对账.md)。

## 4.4 参数合法性条件与公共类型

接口层参数校验遵循 **"文档先行、代码后补"** 的原则：每个 OpenAPI 接口的输入参数在 `design-docs/api-define/OpenAPI接口定义/*.md` 中都有明确的 `合法性条件` 列，复杂或复用的参数类型进一步收敛到 `00-common.md` 中统一描述。

### 4.4.1 校验分层

| 校验层级 | 负责内容 | 典型位置 |
|----------|----------|----------|
| 框架层 | 字段类型、必填、基本格式（由 `xreq.BindJSON`/`validate` 标签完成） | `endpoints/*/xxx.go` |
| 公共类型层 | 跨接口复用的原子类型规则（如 Hostname、IP、Port、CIDR、AIModel、ClusterName 等） | 文档：`00-common.md`；代码：各 Manager/Checker |
| 业务层 | 跨字段约束、资源引用存在性、业务状态一致性 | `model/*` Manager |

### 4.4.2 公共类型示例

`00-common.md` 中定义的公共类型包括：

- **网络原子类型**：`Hostname`、`IP Address`、`Port`、`CIDR`
- **业务命名类型**：`AIModel`、`ClusterName`、`ProviderName`、`EntityTypeName`、`UserName`、`Password`、`TokenName`
- **复杂配置类型**：`RouteRule`、`RouteRules`、`QuotaPlan`、`RateLimitPolicy`、`TPMConfig`、`RPMConfig`

接口文档中通过相对链接引用公共类型，例如：

```markdown
| 参数名 | 类型 | 参数含义 | 必填 | 补充描述 | 合法性条件 |
|--------|------|----------|------|----------|------------|
| name | string | 集群名 | Y | 全局唯一 | 必填；类型为 [ClusterName](./00-common.md#15-集群名称clustername) |
```

### 4.4.3 代码实现建议

后续增强代码校验时，建议：

1. 在 `model/*/checker.go` 或 `lib/validate` 中实现与 `00-common.md` 对应的公共校验函数；
2. 各 Manager 在参数入口处调用公共校验，再执行业务校验；
3. 新增接口必须同步更新接口定义文档的 `合法性条件`，优先引用已有公共类型。

    fileName := strings.SplitN(req.URL.Path, "extra_files/", 2)[1]
    extraFile, err := container.ExtraFileManager.FetchExtraFile(req.Context(), fileName)
    if err != nil {
        return nil, err
    }
    if extraFile == nil {
        return nil, xerror.WrapRecordNotExist()
    }
    return extraFile.Content, nil
}

## 6. 设计特点与约定

1. **统一 Endpoint 抽象**：所有接口无论 OpenAPI 还是 InnerAPI，都通过 `xreq.Endpoint` 描述，便于统一注册、鉴权和中间件处理。
2. **子包自治**：每个业务子包独立维护自己的 Endpoint 变量和 Action 函数，`endpoints.go` 仅做合并，不处理业务逻辑。
3. **鉴权粒度**：OpenAPI 使用 `iauth.FA`（普通鉴权）或 `iauth.FAP`（带产品线鉴权）；InnerAPI 统一使用 `iauth.FA` 配合 `ActionExport`。
4. **参数绑定**：通过 `xreq.Bind`、`xreq.BindJSON`、`xreq.BindForm`、`xreq.BindURI` 绑定请求参数，Action 函数内部再补充业务校验。四类绑定函数的 JSON 反序列化、form/URI 类型转换与 tag 校验失败统一包装为 `xerror` PARAM 参数错误（HTTP 422 `Param Illegal`，form/URI 转换失败文案为 `invalid <name>: <value>`），不回显底层解析错误；裸 error 仅允许来自模型/存储层并分别按 `Model`/`DAO` 类型包装（issue #233，见 modifications/2026-10-12-issue-233-bindform-conversion-500）。
5. **模型层调用**：Action 函数不直接访问存储层，统一通过 `stateful/container` 中暴露的 Manager 完成业务处理。
6. **导出接口版本控制**：InnerAPI 通过 `version` 参数实现增量同步，由 `model/iversion_control` 统一管理配置版本。
