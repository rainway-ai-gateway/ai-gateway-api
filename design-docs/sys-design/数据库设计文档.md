# Rainway AI Gateway - 数据库设计文档

## 1. 概述

本文档描述 `ai-gateway-api` 当前代码实现中使用的数据库表结构，覆盖基础配置、集群与实例池、路由规则、证书与附加文件、API Key / Entity / 配额 / 限流、批量任务等全部持久化表。

### 1.1 数据库引擎与访问方式

| 项目 | 说明 |
|------|------|
| 底层驱动 | 标准库 `database/sql` |
| SQL 构建器 | `github.com/didi/gendry`（builder + scanner） |
| 支持数据库 | MySQL 5.7+、SQLite |
| 连接管理 | `stateful/config_database.go`：`NewDB()` / `BFEDB()` |
| 事务封装 | `lib/xdb.go`：`DBContext` / `Transaction` |
| ORM 风格 | 无 ORM，通过 `db` tag 将 Go struct 映射到表字段 |

### 1.2 通用约定

- 所有表均包含 `created_at` 与 `updated_at` 字段。
- MySQL 中 `updated_at` 默认使用 `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`；SQLite 通过 trigger 模拟该行为。
- 数据库 DDL **未声明物理 FOREIGN KEY 外键约束**，表间关系均为逻辑外键，由应用层代码维护。
- 历史表主要使用 `utf8` 字符集；AI 相关表（`api_keys`、`entity_types`、`entities`、`quota_plans`、`rate_limit_policies`、`route_rules` 等）使用 `utf8mb4`。

### 1.3 表清单

按业务模块划分，共 42 张表：

| 模块 | 表名 |
|------|------|
| 基础配置 | `bfe_clusters`、`products`、`domains`、`users`、`user_products`、`config_versions` |
| Provider | `providers`、`k8s_pools` |
| 集群与实例池 | `clusters`、`sub_clusters`、`pools`、`lb_matrices`、`epp_instances`、`epp_assignments` |
| 路由规则 | `route_basic_rules`、`route_advance_rules`、`route_default_rules`、`route_cases`、`ai_route_rules`、`route_rules` |
| 流量镜像 | `traffic_mirror_rules` |
| 证书与附加文件 | `certificates`、`extra_files` |
| API Key / Entity / 配额 / 限流 | `api_keys`、`api_key_id_seq`、`api_key_tokens`、`entity_types`、`entities`、`entity_id_seq`、`quota_plans`、`rate_limit_policies` |
| AI 缓存 | `ai_cache_rules`、`ai_cache_semantic_settings` |

## 3. Provider 与集群实例池表

### 3.1 `providers`

Provider 配置表，集中管理下游模型提供方的接入能力。

```sql
CREATE TABLE `providers` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `name` varchar(255) NOT NULL,
  `description` varchar(1024) NOT NULL DEFAULT 'no desc',
  `model_endpoint` text,
  `models` text,
  `keys` text,
  `instance_pool` text,
  `instance_source` varchar(32) NOT NULL DEFAULT 'instance_pool',
  `k8s_pool_name` varchar(255) DEFAULT NULL,
  `k8s_instance_pool` text,
  `model_protocols` text,
  `time_zone` varchar(255) NOT NULL DEFAULT 'Asia/Shanghai',
  `tiers` text,
  `created_at` datetime NOT NULL,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `name_index` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | bigint(20) | 主键、自增 | 主键 ID |
| `name` | varchar(255) | NOT NULL、唯一 | Provider 唯一标识；合法命名参考 `ClusterName` |
| `description` | varchar(1024) | NOT NULL DEFAULT 'no desc' | 描述 |
| `model_endpoint` | text | NULL | 模型发现端点 JSON，默认 `{schema: "https", uri: "/v1/models"}` |
| `models` | text | NULL | 支持的模型列表 JSON |
| `keys` | text | NULL | API Key 明文列表 JSON；元素为 `{name, key}`。**列类型约束**：该列在库里名为 `api_keys`，启用 DB 落盘加密后整列存 `enc$v1$` 信封（不是合法 JSON），因此列类型必须为文本类（MySQL `MEDIUMTEXT`、SQLite `TEXT`），**不得声明为 `JSON`**，否则 MySQL 严格模式写入报 `Error 3140`（issue #264） |
| `instance_pool` | text | NULL | 后端实例池 JSON；元素为 `{name, addr, weight, port}`；`instance_source=instance_pool` 时必填 ≥1，`instance_source=k8s_pool` 时休眠保留（不参与有效池） |
| `instance_source` | varchar(32) | NOT NULL DEFAULT 'instance_pool' | 实例供给方式：枚举 `instance_pool`（人维护，默认）/ `k8s_pool`（K8s 发现组件经 InnerAPI `/k8s_pools` 维护） |
| `k8s_pool_name` | varchar(255) | NULL | 引用的 K8s 实例池名称（逻辑引用 `k8s_pools.name`，N:1，无删除保护）；`instance_source=k8s_pool` 时必填，`instance_pool` 模式下休眠保留、不生效 |
| `k8s_instance_pool` | text | NULL | K8s 实例池只读镜像 JSON，系统从 `/k8s_pools` 同步；请求携带该字段返回 422 |
| `model_protocols` | text | NULL | 支持的模型访问协议 JSON；枚举：`openai`、`anthropic`、`gemini` |
| `time_zone` | varchar(255) | NOT NULL DEFAULT 'Asia/Shanghai' | 计算时段所使用的时区；IANA 时区名 |
| `tiers` | text | NULL | 时段 tier 定义列表 JSON；元素为 `{name, time_ranges}`；**初期 `name` 只支持 `peak`** |
| `created_at` | datetime | NOT NULL | 创建时间 |
| `updated_at` | timestamp | 自动更新 | 更新时间 |

> 说明：`time_zone` / `tiers` 描述该 provider 的时段规则，供 InnerAPI 导出 `AIConf.ModelTable` 时使用。同一 provider 下所有模型共享该规则。

> 说明：`providers` 表使用 `utf8mb4` 字符集以支持模型名等多语言内容。Provider 被 `/clusters` 引用时不可删除；`/model-prices` 中的同名 provider 不再阻塞删除。

> 说明：存量行由 `instance_source` 默认值 `'instance_pool'` 兜底，即现状行为，零数据迁移。`k8s_pool_name` / `k8s_instance_pool` 的语义见 [k8s-pools.md](../api-define/InnerAPI接口定义/k8s-pools.md)。

### 3.2 `k8s_pools`

K8s 实例池表，成员列表的唯一写入方是 K8s 发现组件（service-controller），经 InnerAPI `/k8s_pools` 全量维护；引用该池的 provider（`instance_source=k8s_pool`）上 `k8s_instance_pool` 为系统维护的只读镜像。

```sql
CREATE TABLE `k8s_pools` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `name` varchar(255) NOT NULL,
  `instances` text,
  `created_at` datetime NOT NULL,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `name_index` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | bigint(20) | 主键、自增 | 主键 ID |
| `name` | varchar(255) | NOT NULL、唯一 | K8s 实例池名称；普通名称校验，与 K8s Service 名无耦合（Service→池名映射由发现组件自行约定） |
| `instances` | text | NULL | 实例列表 JSON；发现组件全量替换写入（空数组合法，表示"零实例"）；元素为 `{addr, port, weight}`，`weight` 缺省 100 |
| `created_at` | datetime | NOT NULL | 创建时间 |
| `updated_at` | timestamp | 自动更新 | 更新时间；导出侧作为 pool 条目的 `last_sync_time` |

> 说明：同一份实例列表可被多个 provider 引用（N:1），provider 可引用尚不存在的 pool（池不存在 ≡ 零实例）；删除 pool 无引用保护，引用者的 `k8s_instance_pool` 置空、cluster 派生池清空（单事务内完成）。


| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|

| `next_seq` | BIGINT | NOT NULL DEFAULT 1 | 下一个可用序号；分配即消耗，删除 API-Key 后不回退 |

**分配语义**：`next_seq` 表示下一个可用序号。MySQL 通过单条 `INSERT ... ON DUPLICATE KEY UPDATE` + `LAST_INSERT_ID()` 原子自增并读回；SQLite 通过 `INSERT OR IGNORE` + `UPDATE` + 读回。已分配序号永久消耗，即使后续创建失败或事务回滚也不会复用。

> 说明：`api_key_id_seq` 与业务表无外键关系；`next_seq` 必须初始化为当前最大 `api-key-N` 序号 + 1（升级脚本见对应 modifications 文档）。

### 6.15 `batch_tasks`

```sql
CREATE TABLE `batch_tasks` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
```

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | 主键、自增 | 主键 ID |
| `batch_id` | VARCHAR(128) | NOT NULL | provider 侧 batch ID（业务标识，详情/取消端点寻址键） |
| `api_key_id` | VARCHAR(128) | NOT NULL、索引 | API-Key ID（逻辑引用 `api_keys.id`） |
| `product_name` | VARCHAR(128) | NOT NULL | 产品线名称（管控 API 强制隔离维度，不允许外部传参覆盖） |
| `entity_id` | VARCHAR(128) | NULL | Entity ID（可空） |
| `provider` | VARCHAR(128) | NOT NULL | provider 名 |
| `key_name` | VARCHAR(128) | NULL | 控制面直调 provider（cancel / 兜底结算下载输出文件）用 key 名 |
| `endpoint` | VARCHAR(256) | NULL | 批量端点 |
| `input_file_id` | VARCHAR(128) | NULL | 输入文件 ID |
| `output_file_id` | VARCHAR(128) | NULL | 输出文件 ID（状态推进时发现即补登记输出 `batch_files`） |
| `status` | VARCHAR(16) | NOT NULL、索引 | 状态机，对齐 OpenAI：`validating`/`queued`/`in_progress`/`finalizing`/`completed`/`expired`/`failed`/`cancelled`/`cancelling`；二期方言（Anthropic `ended`、Gemini `deleted`）为枚举增量；provider 返回状态原样存、终态不回退 |
| `request_counts` | JSON | NULL | 请求计数对象（provider 原样） |
| `est_lines` | INT | NULL | 预估行数 |
| `usage_input_tokens` / `usage_output_tokens` | BIGINT | NULL | 结算 input/output tokens |
| `usage_source` | VARCHAR(16) | NULL | 用量来源：`download`（下载拦截解析）/ `reconcile`（对账 job 兜底解析） |
| `reserve_units` | BIGINT | NULL | 预留金额（1e-8 定点 RMB，与数据面同口径：行数 × 预估 token 上限 × batch 价） |
| `settle_units` | BIGINT | NULL | 实结金额（1e-8 定点 RMB；实结允许透支预留，`over_reserved=1` 标记） |
| `settle_status` | VARCHAR(16) | NOT NULL | 三态对账主字段：`reserved` / `settled` / `released`；兜底结算与释放均按 `WHERE settle_status='reserved'` 条件更新推进，防双倍结算 |
| `over_reserved` | TINYINT | DEFAULT 0 | 实际超出预留标记 |
| `sync_source` | VARCHAR(8) | DEFAULT `redis` | 同步来源：`redis` / `log`（日志补登标记，对账巡检告警） |
| `idem_key` | VARCHAR(128) | NOT NULL、唯一 | 幂等键，恒等于 `batch_id`；Redis SCAN 同步 upsert 的冲突定位键 |
| `created_at` / `updated_at` / `terminal_at` | DATETIME | `updated_at` 自动更新 | 创建/更新/进入终态时间；`idx_terminal` 支撑终态保留期清理 |

> 说明：
> - **三态对账**：创建时预留（`settle_status='reserved'`）；completed 按结果文件实际 usage 实结（`settled`，允许透支并打 `over_reserved`）；expired/failed/cancelled（cancel 受理）整额释放（`released`）。
> - **cancel 抢占**：`POST /batches/{id}/cancel` 以 `UPDATE ... SET status='cancelling' WHERE batch_id=? AND status NOT IN (终态)` 条件更新抢占，affected_rows=0 返回 409；与对账 job 的结算/释放经 Redis `BATCH_SETTLED` 与 `reserved_units 清零` 两把幂等锁收敛竞态。
> - **TTL 与丢失窗口**：Redis `BATCH_TASK` 键 TTL 48h ≫ 对账 job 1min 同步周期，无丢失窗口；键自然消亡后任务实体以本表为权威。
> - SQLite 版本照 `batch_files` 惯例改写（`INTEGER PRIMARY KEY AUTOINCREMENT`、无 `KEY` 定义、JSON 列以 TEXT 承载、`updated_at` 触发器维护）；新表对存量库为零迁移（纯新增）。
> - 详细状态机、三态金额语义、对账 job 与多实例机制见 [details/批量任务与对账.md](./details/批量任务与对账.md)。

## 9. 备注

1. **无物理外键**：所有表关系靠业务代码维护，删除时需注意级联清理（例如 `DeleteAPIKey` 会同步删除关联的 quota、rate_limit、route_rules 等）。
2. **`users` 表复用**：普通用户与 API Token 共用 `users` 表，通过 `type` 字段区分：0=普通用户，1=Token。
